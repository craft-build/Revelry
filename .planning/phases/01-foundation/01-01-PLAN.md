<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frontend → Tauri IPC | Untrusted webview input crosses to Rust backend |
| Rust → OS Keychain | Backend accesses system credential store |
| Rust → SQLite | Backend accesses local database file |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | S | IPC commands | mitigate | Typed input validation in Rust commands — reject invalid key_name, empty required fields |
| T-01-02 | T | Keychain commands | mitigate | Key names sanitized — no arbitrary key access, validate format before keyring call |
| T-01-03 | I | SQLite DB file | accept | Local-only app, DB in user AppData, OS file permissions sufficient |
| T-01-04 | D | API keys in keychain | accept | OS keychain provides integrity, local-only access |
| T-01-05 | E | Tauri capabilities | mitigate | Deny-by-default capability model, explicit permission grants only (no blanket) |
| T-01-06 | D | API key storage | mitigate | keyring crate exclusively — grep for api_key column in schema returns 0 matches in CREATE TABLE |
</threat_model>
