1. Create `src/service/token_count.rs`:
   - `pub const DEFAULT_CONTEXT_WINDOW: i64 = 8192;`
   - `pub struct TokenCountService` with a cached tiktoken core BPE tokenizer:
     - On first call, initialize `tiktoken_rs::core::cl100k_base()` (per D-03, single tokenizer for all providers)
     - Wrap in `std::sync::Mutex<Option<CoreBPE>>` for lazy init
   - `pub fn count_tokens(&self, text: &str) -> usize` — tokenize and count, applying 10% safety margin (round up: `count + count / 10`). Per D-03.
   - `pub fn resolve_context_window_size(&self, provider: &ProviderConfig) -> i64` — 3-tier fallback per D-02:
     1. If `provider.context_window_size` is Some(n) and n > 0, return n (user override)
     2. Look up `provider.model_name` in built-in defaults table (HashMap<&str, i64>)
     3. Fall back to DEFAULT_CONTEXT_WINDOW
   - Built-in default table (partial list, covering most common models):
     - "gpt-4o" → 128000, "gpt-4o-mini" → 128000, "gpt-4-turbo" → 128000
     - "claude-sonnet-4-20250514" → 200000, "claude-3-5-sonnet" → 200000
     - "llama3.2" → 8192, "llama-3.3-70b-versatile" → 128000
     - "deepseek-chat" → 65536, "mistral-large-latest" → 128000
     - "gemini-2.0-flash" → 1048576
     - Match using model name starts_with / contains for flexibility
   - `pub fn count_message_tokens(&self, preamble: &str, messages: &[Message]) -> usize` — count preamble tokens + sum of message tokens (each message: role overhead ~4 tokens + content tokens)

2. Add `pub mod token_count;` to `src/service/mod.rs`.
