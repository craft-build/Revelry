Per D-09, D-10, D-11, D-12, D-13: Create lorebook activation engine.

1. Create `src/service/lorebook.rs`:

2. `pub struct ActivatedEntry`:
   - `pub entry: LorebookEntry` — the original entry
   - `pub injected_content: String` — possibly truncated content (after token budget enforcement)
   - `pub effective_depth: i32` — the depth-from-bottom where this entry injects

3. `pub fn activate_lorebook_entries(...)`:
   ```rust
   pub fn activate_lorebook_entries(
       all_entries: &[LorebookEntry],
       recent_messages: &[Message],
       scan_depth: i32,          // how many recent messages to scan (D-10)
       max_recursive_depth: i32, // recursive activation limit (D-12, default 2)
       lorebook_token_budget: i64, // total tokens available for lorebook layer
       token_service: &TokenCountService,
   ) -> Vec<ActivatedEntry>
   ```

   Algorithm:
   a. Filter to enabled entries only
   b. Take the last `scan_depth` messages as scan scope (per D-10)
   c. Concatenate those messages' content into a scan text
   d. **Initial scan**: For each enabled entry, check if ANY keyword or secondary_term appears in scan text (OR logic, case-insensitive, per D-09). Collect matching entries.
   e. **Recursive activation** (per D-12): 
      - Iteration 1: Check if content of newly-activated entries contains keywords of NOT-yet-activated entries
      - Iteration 2: Check if content of entries activated in iteration 1 contains more keywords
      - Repeat up to `max_recursive_depth` iterations (default 2)
      - Track which entries have been activated to prevent duplicates
   f. **Token budget enforcement** (per D-13):
      - Calculate total tokens available for lorebook layer
      - Sort activated entries by sort_order
      - For each entry:
        - If entry has explicit token_budget: truncate content from end if it exceeds budget
        - If entry has no token_budget: track remaining budget from the lorebook allocation
      - Overflow: entries under budget free tokens for subsequent entries
   g. Return Vec<ActivatedEntry> sorted by sort_order, each with their effective depth_from_bottom

4. `pub fn inject_lorebook_entries(preamble: &str, entries: &[ActivatedEntry], messages: &mut Vec<Message>) -> String`:
   - For depth_from_bottom = 0 entries: append to preamble (after character definition)
   - For depth > 0 entries: inject into chat history at N messages from end
   - Returns the modified preamble (lorebook content appended to system prompt section)
   - Modifies messages in place for depth-based injections

5. Helper function `fn keyword_matches(keywords: &[String], text: &str) -> bool`:
   - Case-insensitive check if ANY keyword appears in text (OR logic, per D-09)
   - Use `text.to_lowercase().contains(keyword.to_lowercase().as_str())` for each keyword

6. Add `pub mod lorebook;` to `src/service/mod.rs`.

7. Write comprehensive tests in `src/service/lorebook.rs` covering all behavior items. Create test fixtures with LorebookEntry and Message objects.
