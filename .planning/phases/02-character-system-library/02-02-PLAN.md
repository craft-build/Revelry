    1. Create `src/service/card_io.rs` with the following public functions:

    2. `pub fn import_from_json(json_str: &str) -> Result<CharacterCardV2>`:
       - Check payload size < 10MB, return Err if exceeded
       - Try serde_json::from_str::<CharacterCardV2> first (V2 format)
       - If fails, try serde_json::from_str::<CharacterV1> (V1 format) and call .to_v2()
       - If both fail, return descriptive error with context about expected formats
       - Return the CharacterCardV2 with a new UUID v4 id (per import semantics — imported characters get new IDs)

    3. `pub fn export_to_json(character: &CharacterCardV2) -> Result<String>`:
       - serde_json::to_string_pretty(character) for human-readable output

    4. `pub fn import_from_png(png_bytes: &[u8]) -> Result<(CharacterCardV2, Option<Vec<u8>>)>`:
       - Parse PNG using png crate: `png::Decoder::new(std::io::Cursor::new(png_bytes))`
       - Read info and iterate tEXt chunks looking for key "chara"
       - Base64-decode the value string using base64 crate
       - Pass decoded string to import_from_json() for V1/V2 detection
       - Return (character, Some(raw_png_bytes)) if avatar should be extracted from the PNG itself (the PNG IS the avatar image)
       - Return error if no "chara" tEXt chunk found

    5. `pub fn export_to_png(character: &CharacterCardV2, avatar_bytes: Option<&[u8]>) -> Result<Vec<u8>>`:
       - Serialize character to JSON with serde_json::to_string
       - Base64-encode the JSON string
       - If avatar_bytes provided, read the PNG and add tEXt chunk
       - If no avatar, create a minimal 1x1 PNG with just the tEXt chunk embedded
       - For PNG writing: use png::Encoder, add tEXt chunk with pair ("chara", base64_encoded_json)
       - Return the PNG bytes

    6. Update `src/service/mod.rs` to add `pub mod card_io;`

    7. Write all unit tests in `#[cfg(test)] mod tests` block. Use a known CharacterCardV2 test fixture for roundtrip tests.
