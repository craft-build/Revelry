## Phase Scope — New UI Elements

This phase adds one new interaction surface, one new CSS block, and modifies four existing surfaces:

### New Surfaces

1. **Theme toggle button group** — three-way segmented control (System / Light / Dark) in Settings > Appearance section (D-05, D-06, D-07)
2. **Light theme token overrides** — `.light` CSS selector block in `app.css` overriding all `@theme` tokens with cool-toned light equivalents (D-01, D-02, D-03, D-04, D-13)

### Modified Surfaces

3. **Settings > Appearance section** — replace stub text with theme toggle component + descriptive text (D-08)
4. **app.html `<html>` element** — add inline flash-prevention script that reads localStorage and sets `.light` or `.dark` class before hydration (D-14)
5. **AppState** — add `theme` field and `resolved_theme` derived getter (D-17)
6. **MarkdownRenderer + Layout Shiki preloader** — load both `vitesse-dark` and `vitesse-light`, select active based on resolved theme (D-15)
7. **All existing components** — full visual polish audit: transitions, animations, spacing consistency, hover states, focus rings (D-09, D-10, D-11, D-12)

All new elements use existing component primitives and Tailwind v4 `-(--token)` convention. The light theme works by overriding CSS custom properties — no component-level conditional classes needed.

## Color

### Light Theme Tokens

All tokens defined in OKLCH. Light theme uses cool-toned palette in the 270 hue family (D-01), with soft/off-white surfaces (D-02, oklch 0.94–0.97 range). Not stark white — Notion/Bear aesthetic.

The `.light` selector block overrides every token from `@theme`:

| -------------------------- | ----------------------- | ----------------------- | --------------------------------------------------------------- |

## Interaction Contracts

### 1. Theme Toggle Button Group

**Where:** Settings > Appearance section, inside the existing card container.

**Layout:**

- Contained in a card matching existing settings card style: `rounded-(--radius-lg) border border-(--color-border) bg-(--color-surface) p-4`
- Section header: "Theme" in `font-display text-base font-semibold tracking-tight text-(--color-foreground)`
- Description: "Choose how Revelry looks. System follows your OS preference." in `text-sm text-(--color-muted) mt-1`
- Toggle group: below description, `mt-4`
  - Container: `inline-flex rounded-(--radius-lg) border border-(--color-border) bg-(--color-background) p-1 gap-1`
  - Each button: `rounded-(--radius-md) px-4 py-2 text-sm font-medium transition-all duration-150`
  - Active state: `bg-(--color-surface-elevated) text-(--color-foreground) shadow-sm`
  - Inactive state: `text-(--color-muted) hover:text-(--color-foreground)`
  - Buttons: "System" (Monitor icon) | "Light" (Sun icon) | "Dark" (Moon icon)
  - Icons: `size-4` inline with text, `gap-1.5`

**Annotation below toggle:**

- Dynamic text that changes based on selection:
  - System selected: "Following your system preference ({resolved})" — e.g. "Following your system preference (dark)"
  - Light selected: "Light theme active"
  - Dark selected: "Dark theme active"
- Style: `text-xs text-(--color-subtle) mt-2`
- The resolved value for System updates reactively when OS preference changes

**Interaction:**

- Click a button → `app.setTheme('system' | 'light' | 'dark')` →
  1. localStorage updated immediately
  2. `<html>` class toggled (`.light` or `.dark`) — CSS custom properties change, entire app re-themes instantly
  3. Backend `set_app_setting('theme', value)` called asynchronously (non-blocking)
- No page reload. No flash. Theme applies immediately.
- On "System" selection, listen for `matchMedia('(prefers-color-scheme: dark)')` changes and auto-resolve

**Transition behavior:**

- When theme switches, all components transition smoothly via `transition-colors duration-150`
- This is a global feel — not individual component animations. The color tokens change, and any element already using `transition-colors` gets the smooth crossfade automatically
- For elements without existing `transition-colors`, add it during the polish audit

### 2. Flash Prevention Script

**Where:** Inline `<script>` in `app.html` `<head>`, before any stylesheets load.

**Logic:**

```html
<script>
  (function () {
    try {
      var theme = localStorage.getItem("revelry-theme") || "system";
      var resolved;
      if (theme === "system") {
        resolved = window.matchMedia("(prefers-color-scheme: light)").matches
          ? "light"
          : "dark";
      } else {
        resolved = theme;
      }
      document.documentElement.classList.add(resolved);
    } catch (e) {
      document.documentElement.classList.add("dark");
    }
  })();
</script>
```

**Requirements:**

- Must be in `<head>` before Google Fonts and `%sveltekit.head%`
- No `await`, no modules, no external dependencies
- Fallback to `dark` on any error (matches current behavior)
- Removes need for hardcoded `class="dark"` on `<html>` element

### 3. Shiki Theme Pairing

**Dark theme:** `vitesse-dark` (existing from Phase 7)
**Light theme:** `vitesse-light` (new, D-15)

**Preloader changes (+layout.svelte):**

- Load both themes at app startup (currently only loads `vitesse-dark`)
- Store both highlighters
- Pass active highlighter to MarkdownRenderer based on `app.resolved_theme`

**MarkdownRenderer changes:**

- Accept `theme` prop or read `app.resolved_theme` directly
- Use the appropriate pre-loaded highlighter
- No re-initialization needed — just swap which cached highlighter is used
- Transition: no animation on code blocks (instant switch is fine — syntax highlighting changes are not jarring)

### 4. Full Polish Audit (D-09, D-10, D-11, D-12)

**Animation philosophy:** Subtle and fast (150–200ms). Felt, not seen. Content-first. (D-10)

**Transition targets and specifications:**

| Target                | Property                                    | Duration | Easing                          | Implementation                                                            |
| --------------------- | ------------------------------------------- | -------- | ------------------------------- | ------------------------------------------------------------------------- |
| Sidebar open/close    | `transform` or `width`                      | 200ms    | `cubic-bezier(0.4, 0, 0.2, 1)`  | CSS transition on sidebar container width/margin                          |
| Message appear        | `opacity` + `transform`                     | 150ms    | `ease-out`                      | Svelte `transition:fade` or `transition:slide` on new MessageBubble mount |
| Route cross-fade      | `opacity`                                   | 150ms    | `ease-out`                      | Svelte `transition:fade` on route outlet                                  |
| Hover states (all)    | `background-color`                          | 150ms    | `ease-out`                      | CSS `transition-colors` (most already have this)                          |
| Focus rings           | `outline`                                   | 100ms    | `ease-out`                      | Existing `:focus-visible` — verify consistency                            |
| Theme switch          | `color`, `background-color`, `border-color` | 150ms    | `ease-out`                      | Global `transition-colors` on body/container                              |
| Popover open/close    | `opacity` + `scale`                         | 150ms    | `cubic-bezier(0.16, 1, 0.3, 1)` | Svelte transition or CSS animation on Popover                             |
| Dialog open/close     | `opacity` + `scale`                         | 200ms    | `cubic-bezier(0.16, 1, 0.3, 1)` | bits-ui Dialog transition (if customizable)                               |
| Streaming caret blink | `opacity`                                   | 1000ms   | `steps(2)`                      | Existing — no change                                                      |

**Hover state audit targets:**

- All interactive elements must have a visible hover state
- Hover must use `--color-surface-hover` for backgrounds
- Text color must transition to `--color-foreground` on hover
- Consistent `transition-colors duration-150` across all interactive elements

**Focus ring audit targets:**

- All interactive elements must have `:focus-visible` ring
- Ring: `2px solid var(--color-accent)` with `outline-offset: 2px`
- Ring must be visible in both light and dark themes
- Keyboard-only (`:focus-visible`, not `:focus`) — no rings on click

**Spacing audit targets:**

- Verify 8-point scale adherence across all components
- Flag any non-multiple-of-4 spacing values
- Ensure consistent padding within component categories (cards, list items, buttons, inputs)

## State Contract

### New AppState Fields

| Field   | Type                                    | Default    | Description                                                                                |
| ------- | --------------------------------------- | ---------- | ------------------------------------------------------------------------------------------ |
| `theme` | `$state<'system' \| 'light' \| 'dark'>` | `'system'` | User's theme preference. Persisted to localStorage immediately and backend asynchronously. |

### New AppState Getters

| Getter           | Returns             | Logic                                                                                                                                                          |
| ---------------- | ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `resolved_theme` | `'light' \| 'dark'` | If `theme === 'system'`, reads `window.matchMedia('(prefers-color-scheme: dark)')` → `'dark'` if true, `'light'` if false. Otherwise returns `theme` directly. |

### New AppState Actions

| Method            | Parameters                             | Behavior                                                                                                                                                                                                                 |
| ----------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `setTheme(theme)` | `theme: 'system' \| 'light' \| 'dark'` | 1. Set `this.theme = theme`. 2. `localStorage.setItem('revelry-theme', theme)`. 3. Update `<html>` class to `resolved_theme`. 4. Call `invoke('set_app_setting', { key: 'theme', value: theme })` (async, non-blocking). |

### Hydration Changes

- `app.hydrate()` must load theme from backend via `invoke('get_app_setting', { key: 'theme' })` on startup
- If backend returns a value, use it. If null/undefined, default to `'system'`
- After hydration, sync `<html>` class with resolved theme
- Register `matchMedia('(prefers-color-scheme: dark)')` change listener to re-resolve when OS preference changes (only when `theme === 'system'`)

### New API Wrappers (api.ts)

```typescript
getAppSetting(key: string): Promise<string | null>
setAppSetting(key: string, value: string): Promise<void>
```

### Backend Commands (Rust)

```rust
#[tauri::command]
get_app_setting(key: &str, state: State<AppState>) -> Result<Option<String>, String>

#[tauri::command]
set_app_setting(key: &str, value: &str, state: State<AppState>) -> Result<(), String>
```

Uses existing `app_settings` table (key TEXT PRIMARY KEY, value TEXT NOT NULL) from migrations.
