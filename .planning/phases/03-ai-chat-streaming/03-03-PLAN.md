         ```
         EditMessage { message_id: String, new_content: String },  // user edited a message
         RegenerateMessage(String),  // message ID to regenerate
         DeleteMessage(String),       // message ID to delete
         SwitchBranch(Option<String>), // switch to branch_id (None = root)
         BranchesLoaded(Vec<MessageBranch>), // from DB
         MessageContentUpdated,        // from DB after edit
         MessageDeleted(String),      // from DB after delete
         ```
       - Add ChatPanelOutput variants:
         ```
         EditMessage { message_id: String, new_content: String },
         RegenerateMessage(String),
         DeleteMessage(String),
         LoadBranches(String),        // load branches for a parent message
         UpdateMessageContent { id: String, content: String },
         ```
       - Handle EditMessage per D-11:
         1. Create a new MessageBranch: `MessageBranch::new(conversation_id, Some(message_id), format!("Edit {}", branch_count))`
         2. Save branch to DB
         3. Create new user message with edited content in the new branch
         4. Save new message to DB
         5. Load messages for the new branch
         6. Start AI streaming with the new branch's history (messages up to the edit point + new message)
       - Handle RegenerateMessage:
         1. Find the message to regenerate (must be Assistant role)
         2. Find its parent_message_id (the user message that prompted it)
         3. Create a new MessageBranch with the parent as fork point
         4. Start AI streaming with the same history (up to the parent message)
         5. The new response goes into the new branch
       - Handle SwitchBranch:
         1. Set `self.active_branch_id = new_branch_id`
         2. Send ChatPanelOutput::LoadMessages { conversation_id, branch_id: new_branch_id }
         3. On MessagesLoaded: replace self.messages, rebuild FactoryVecDeque
       - Handle DeleteMessage:
         1. Send ChatPanelOutput::DeleteMessage(message_id)
         2. Reload messages for current branch after deletion
       - When loading messages, also query for branches at each message position to set `has_siblings` on MessageRowInit.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User edit → PromptEngine | Edited message content replaces original in prompt — user controls own content |
| Branch data → DB | Branch creation and message editing writes to SQLite — within app trust boundary |
| Delete operation → DB | Message deletion with branch cleanup — irreversible, within user's control |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-12 | T (Tampering) | message_row.rs | accept | User editing their own message is expected behavior — no cross-user risk |
| T-03-13 | D (Denial of Service) | chat/mod.rs | mitigate | Branch creation is bounded by conversation — no infinite branch creation possible (each branch requires user action) |
| T-03-14 | I (Info Disclosure) | branch_nav.rs | accept | Branch data is local SQLite — no disclosure risk beyond existing local storage |
</threat_model>
