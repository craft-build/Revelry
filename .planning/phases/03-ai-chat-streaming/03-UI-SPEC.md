# Phase 3 — UI Design Contract

> Visual and interaction contract for Phase 3 (AI Chat & Streaming). Generated by gsd-ui-researcher.
> This is a GTK4/libadwaita + Relm4 desktop application — not a web frontend. The design system is **Adwaita** (libadwaita), not shadcn.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native GTK4/libadwaita) |
| Preset | Adwaita (libadwaita v1.5+) |
| Component library | GTK4 + libadwaita widgets |
| Icon library | relm4-icons 0.11.0 (bundled Adwaita symbolic icons) |
| Font | System font (Cantarell on GNOME, system-ui on macOS/Windows) |
| CSS framework | GTK CSS (Adwaita stylesheet via libadwaita) |

**Note:** shadcn gate is not applicable — this is a native Rust/GTK4 desktop application, not a React/Next.js/Vite web frontend. The Adwaita design system provides the visual language, CSS classes, and widget styling automatically.

## Spacing Scale

Declared values (multiples of 4, following GNOME HIG spacing conventions):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, tight element spacing |
| sm | 8px | Compact element spacing, search bar margins |
| md | 16px | Default element spacing, list row padding |
| lg | 24px | Section padding, header bar content margins |
| xl | 32px | Layout gaps, major section separators |
| 2xl | 48px | Major section breaks, content clamp margins |
| 3xl | 64px | Page-level spacing, empty state padding |

Exceptions:
- **Touch target minimum:** 44px for interactive elements per GNOME HIG (stop button, send button, sidebar rows)
- **Input bar height:** Min 80px, max 200px for multi-line GtkTextView (per Plan 02 Task 1)
- **Sidebar width:** 280–360px, fraction 0.30 (from existing `app.rs` AdwOverlaySplitView config)

## Typography

Uses Pango markup for formatted rendering. System font via Adwaita stylesheet.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 15px (system default) | 400 (normal) | 1.5 | Message content, conversation preview |
| Label | 13px (small) | 400 (normal) | 1.3 | Character name in message row, timestamp, branch label |
| Heading | 20px (large) | 600 (semibold) | 1.2 | Header bar character name, empty state titles |
| Display | 28px (x-large) | 600 (semibold) | 1.2 | Pango heading level 1 in AI responses |

**Pango markup for AI responses** (per D-06, RESEARCH.md):
- Bold → `<b>...</b>`
- Italic → `<i>...</i>`
- H1 → `<span size="xx-large"><b>...</b></span>`
- H2 → `<span size="x-large"><b>...</b></span>`
- H3 → `<span size="large"><b>...</b></span>`
- Inline code → `<tt>...</tt>`
- Code block → `<tt>...</tt>` (newline-separated)
- List items → `• ...\n`
- All text content MUST pass through `escape_pango()` before wrapping in tags

**Font weights declared:** 2
1. 400 (normal/Pango_WEIGHT_NORMAL) — body text, labels, timestamps
2. 600 (semibold/Pango_WEIGHT_SEMIBOLD) — headings, character names, active state labels

## Color

Uses Adwaita color variables. Light/dark mode supported automatically via `AdwApplication`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `@background_color` / `@view_bg_color` | Chat message area background, main content surfaces |
| Secondary (30%) | `@sidebar_bg_color` / `@card_bg_color` | Sidebar, message row backgrounds, input bar area |
| Accent (10%) | `@accent_color` (blue in Adwaita default) | Send button, active branch indicator, user message background tint, streaming progress |
| Destructive | `@destructive_color` (red in Adwaita default) | Delete action buttons, error state indicator badge |

Accent reserved for:
- Send button active state
- User message row subtle background tint (CSS class `accent`)
- Active/selected branch in BranchNav popover
- Branch indicator left border (colored line)
- Stop button during streaming (overrides with destructive on hover)
- Streaming cursor/indicator

**NOT for:** Character avatar borders, general interactive elements, scrollbars, dividers — those use standard Adwaita styling.

## Interaction States

### ChatPanel Streaming State Machine

```
                    ┌───────────┐
                    │   Idle    │◄──────── StreamComplete / StreamError
                    └─────┬─────┘
                          │ SendMessage
                          ▼
                    ┌───────────┐
                    │ Streaming │──────── CancelStream ──► Save partial, → Idle
                    └─────┬─────┘
                          │ Escape / Stop button
                          ▼
                    ┌───────────┐
                    │ Cancelling│──────── Partial saved ──► Idle
                    └───────────┘
```

### Message Row States

| State | Visual | Interaction |
|-------|--------|--------------|
| Normal (assistant) | Left-aligned, character avatar + name, Pango body | Right-click → context menu (Regenerate, Delete) |
| Normal (user) | Right-aligned, accent tint, "You" label, escaped body | Right-click → context menu (Edit, Delete) |
| Streaming (assistant) | Left-aligned, plain text (no Pango), cursor/indicator | No context menu during streaming |
| Error (partial) | Left-aligned, body + error badge (⚠ icon), dimmed | Right-click → context menu (Retry, Edit, Delete) |
| Has branches | Colored left border (2px accent), branch count badge | Click badge → BranchNav popover |

### Conversation List States

| State | Visual | Interaction |
|-------|--------|--------------|
| Active conversation | Selected state, accent background | Click → load in ChatPanel |
| Inactive conversation | Normal row style | Click → load in ChatPanel |
| New conversation row | "+" icon, "New Conversation" label | Click → character selection / first available provider |

### Input Bar States

| State | Visual | Interaction |
|-------|--------|--------------|
| Empty | Send button disabled (opacity 0.5) | Type to enable |
| Has text | Send button active (accent color) | Ctrl+Enter or click to send |
| Sending (streaming) | Send button hidden, Stop button visible (destructive red) | Click Stop or Escape to cancel |
| Multi-line | Text area grows from 80px to 200px max | Scroll if exceeds 200px |

## Streaming Rendering Strategy (per RESEARCH.md Pitfall #1)

| Phase | Rendering | Rationale |
|-------|-----------|-----------|
| **During streaming** | Plain text accumulation, no Pango markup conversion | Per-token markdown re-render would block GTK main loop |
| **Debounce** | Re-render Pango every 100ms or every 5 tokens (whichever first) | Balance between visual feedback and performance |
| **On stream complete** | Full `markdown_to_pango()` conversion of accumulated text | Final render with all formatting |
| **On cancel** | Full `markdown_to_pango()` conversion of partial text | Partial message gets full formatting before save |
| **Error** | No re-render — keep plain text, add error badge | Error state is terminal for that message |

## Scroll Behavior

| Event | Action |
|-------|--------|
| New message appended | Auto-scroll to bottom (smooth) |
| Streaming token received | Stay at bottom if already at bottom; don't force-scroll if user scrolled up |
| Load conversation | Scroll to bottom after all messages rendered |
| Branch switch | Scroll to fork point, then smooth-scroll to end of new branch |
