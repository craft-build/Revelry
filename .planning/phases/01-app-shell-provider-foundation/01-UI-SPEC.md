# Phase 1 — UI Design Contract

> Visual and interaction contract for App Shell & Provider Foundation. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Adapted for GTK4/libadwaita native desktop — not a web/shadcn project.

## Spacing Scale

Adwaita uses GTK logical pixels (not CSS px). Standard spacing follows multiples of 4:

| Token | GTK Value | Usage |
|-------|-----------|-------|
| xs | 4 | Icon gaps, inline padding within compact controls |
| sm | 8 | Compact element spacing, inner widget padding |
| md | 12 | Default element spacing (Adwaita standard `set_spacing`) |
| lg | 16 | Section padding, content margins within AdwClamp |
| xl | 24 | Section breaks, AdwPreferencesGroup spacing |
| 2xl | 32 | Page-level padding, sidebar/content margins |
| 3xl | 48 | Major section breaks, welcome/empty state spacing |

Exceptions:
- AdwPreferencesWindow internal spacing is managed by libadwaita (not overridden)
- AdwOverlaySplitView sidebar width: 280px minimum, 360px default (Adwaita standard)
- Touch targets: minimum 32×32 GTK logical pixels for interactive elements (GNOME HIG recommends 24px minimum for pointer, 32px for touch; Adwaita widgets enforce this automatically)
- AdwBreakpoint collapse threshold: 720px wide (standard Adwaita breakpoint for sidebar collapse)

## Typography

Use Adwaita CSS style classes exclusively — never hard-code font sizes or weights. The system font is Adwaita Sans (Inter variant), weight 400 regular / 700 bold.

| Role | Adwaita CSS Class | Approx. Size | Weight | Line Height | Usage |
|------|-------------------|-------------|--------|-------------|-------|
| Body | `.body` | 14pt equivalent | 400 (regular) | 1.5 | Default labels, descriptions, conversation list items |
| Heading | `.heading` | 16pt equivalent | 700 (bold) | 1.2 | Section titles in preferences, group headers |
| Caption | `.caption` | 12pt equivalent | 400 (regular) | 1.4 | Sub-text, timestamps, secondary info |
| Caption Heading | `.caption-heading` | 12pt equivalent | 700 (bold) | 1.4 | Caption labels that need emphasis |
| Title 4 | `.title-4` | 18pt equivalent | 700 (bold) | 1.2 | Provider config page title |
| Title 1 | `.title-1` | 24pt equivalent | 800 (extra-bold) | 1.1 | Welcome/empty state display heading |

**Key rule:** Never hard-code `font-size` or `font-family` in custom CSS. Always use Adwaita style classes. This ensures proper behavior under high-contrast mode, accessibility scaling, and platform font differences.

## Color

Adwaita provides semantic CSS variables that automatically adapt to light/dark/high-contrast modes. Use these variables exclusively — never hard-code hex values.

| Role | CSS Variable | Light Mode Approx. | Dark Mode Approx. | Usage |
|------|-------------|---------------------|-------------------|-------|
| Dominant (60%) | `--window-bg-color` | #ffffff | #1c1c1c | Main window background, content area |
| Secondary (30%) | `--card-bg-color` / `--sidebar-bg-color` | #f6f5f4 | #2d2d2d | Sidebar, preference groups, boxed lists |
| Accent (10%) | `--accent-bg-color` | #3584e4 (blue) | #3584e4 | See reserved-for list below |
| Destructive | `--destructive-bg-color` | #e01b24 | #e01b24 | Delete provider confirmation only |
| Success | `--success-bg-color` | #33d17a | #33d17a | Provider test success indicator |
| Warning | `--warning-bg-color` | #f6d32d | #e5a50a | Provider test partial/warning state |
| Error | `--error-bg-color` | #e01b24 | #e01b24 | Provider test failure, keyring errors |

**Accent reserved for (explicit list):**
- `suggested-action` buttons (Add Provider, Test Connection)
- Active view switcher tab indicator
- Selected sidebar conversation highlight
- Active/focused text field border
- Progress/spinner during provider test (uses accent color)

**Destructive reserved for:**
- Delete provider button (with confirmation dialog)
- No other destructive actions in Phase 1

**Style class usage for state feedback:**
- `.suggested-action` → accent blue for primary actions
- `.destructive-action` → red for delete actions
- `.accent` → accent-colored label text for emphasis
- `.success` → green for provider test success
- `.warning` → yellow for provider test warning
- `.error` → red for provider test failure / keyring errors

## Widget Hierarchy

### Main Window Structure

```
AdwApplicationWindow
├── AdwToastOverlay                    // Top-level toast container
│   └── AdwOverlaySplitView            // Adaptive sidebar/content
│       ├── sidebar: AdwToolbarView
│       │   ├── top: AdwHeaderBar      // Sidebar header (optional title)
│       │   └── content: GtkListBox     // Conversation list (.navigation-sidebar)
│       │       └── [conversation rows or empty state]
│       └── content: AdwToolbarView
│           ├── top: AdwHeaderBar      // Main header with view switcher
│           │   └── AdwViewSwitcher    // Chat | Characters | Settings
│           └── content: GtkStack       // Switched by active_view enum
│               ├── ChatView            // Chat panel (empty state in Phase 1)
│               ├── CharactersView      // Characters panel (empty state in Phase 1)
│               └── SettingsView        // Settings panel (active in Phase 1)
```

### Sidebar Detail

```
GtkListBox (.navigation-sidebar)
├── [When conversations exist]
│   └── GtkListBoxRow per conversation
│       ├── GtkLabel (.heading)         // Conversation title
│       ├── GtkLabel (.caption, .dimmed) // Character name + timestamp
│       └── GtkLabel (.caption)          // Last message preview (truncated)
├── [When no conversations]
│   └── AdwStatusPage                   // Empty state placeholder
│       ├── icon-name: "chat-message-new-symbolic"
│       ├── title (.title-1): "No Conversations Yet"
│       └── description (.body): "Start by configuring a provider in Settings."
```

### Settings Panel Structure

```
GtkStack child: SettingsView
└── AdwClamp                            // Constrained width for readability
    └── GtkBox (vertical, spacing: xl)
        └── AdwPreferencesGroup "AI Providers"
            ├── GtkLabel (.heading)     // Group title
            ├── [When providers exist]
            │   └── AdwActionRow per provider (.boxed-list)
            │       ├── title: provider name
            │       ├── subtitle: provider type + status
            │       ├── suffix: GtkButton "Edit" (.flat)
            │       ├── suffix: GtkButton "Test" (.flat)
            │       └── suffix: GtkButton "Delete" (.flat, .destructive-action on hover)
```

### Provider Configuration Page (AdwPreferencesWindow sub-page)

```
AdwPreferencesWindow
└── AdwPreferencesPage "Provider Configuration"
    ├── AdwPreferencesGroup "Provider Type"
    │   └── AdwComboRow                 // Provider type selector
    │       ├── OpenAI, Anthropic, Ollama, Gemini, etc.
    │       └── [On select → show type-specific fields below]
```

## Loading & Progress Indicators

| Context | Widget | Rationale |
|---------|--------|-----------|
| Provider connection test | GtkSpinner (indeterminate) | Connection test duration is variable and unknown. Indeterminate spinner is the Adwaita standard for indeterminate-duration async operations. Not a progress bar — we don't know the total. |
| Database migration (startup) | None (must complete before UI renders) | rusqlite_migration runs synchronously during init. App does not render until complete. Fast enough (< 100ms for Phase 1 schema) that no indicator is needed. |
| Keyring access | None (background thread, < 50ms) | Runs on Worker thread. Fast enough that no indicator is needed. Error surfaces via toast if it fails. |

## Adwaita Breakpoint Configuration

```rust
// AdwBreakpoint for sidebar collapse
// At widths < 720px: sidebar collapses to overlay mode
// At widths >= 720px: sidebar shows side-by-side

// In view! macro:
adw::OverlaySplitView {
    set_sidebar_width_fraction: 0.30,  // 30% of window width
    set_min_sidebar_width: 280,
    set_max_sidebar_width: 360,
    set_collapsed: false,  // Default to side-by-side

    #[wrap(Some)]
    set_breakpoints: adw::Breakpoint::new(adw::BreakpointCondition::new_length(
        adw::BreakpointConditionLengthType::MaxWidth,
        720.0,
        adw::LengthUnit::Pt,
    )) {
        add_setter: (&split_view, "collapsed", &true.into()),
    },
}
```

## Interaction Specifications

### Provider Test Flow

1. User clicks "Test Connection" button (`.suggested-action`)
2. Button becomes insensitive (disabled); GtkSpinner appears and starts spinning
3. Async command dispatched to Worker: build rig client from provider config, call health endpoint or list models
4. **On success:** Spinner replaced by GtkImage `emblem-ok-symbolic` (`.success`); GtkLabel shows "N models available" (`.caption`); toast "Connected — {N} models available"
5. **On failure:** Spinner replaced by GtkImage `dialog-error-symbolic` (`.error`); error message displayed below; toast "Connection failed: {error}"
6. Button re-enabled after result

### Provider Delete Flow

1. User clicks "Delete" button on provider row (`.destructive-action` styling)
2. AdwMessageDialog appears: "Remove Provider?" with body text and Cancel/Remove buttons
3. Remove button styled `.destructive-action`
4. **On confirm:** Delete from SQLite + delete from keyring; row removed from list; toast "Provider removed"
5. **On cancel:** Dialog closes, no action

### First Launch Detection

1. On startup, query `SELECT COUNT(*) FROM providers`
2. If count = 0 and no conversations: set `active_view = Settings` and show welcome empty state
3. If count > 0: set `active_view = Chat` and show sidebar + chat empty state
4. This is a one-time redirect — user can switch to Settings anytime via view switcher or Ctrl+Comma
