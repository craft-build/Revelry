## Task 01-04-02: Run `bun tauri build` to produce production binary

<read_first>
- persona/package.json (verify tauri:build script)
- persona/src-tauri/Cargo.toml
- persona/src-tauri/tauri.conf.json
</read_first>

<action>
Run `bun run tauri:build` (or `bun tauri build`) in the project root. This will:
1. Run `bun run build` (the beforeBuildCommand) to produce static frontend files
2. Compile the Rust binary in release mode
3. Bundle everything into a platform-specific installer

On macOS, this produces:
- `src-tauri/target/release/bundle/dmg/Revelry_0.1.0_aarch64.dmg` (or x86_64)
- `src-tauri/target/release/bundle/macos/Revelry.app`

The first build will be slow (Rust release compilation). Subsequent builds are faster due to incremental compilation.

If the build fails:
- Check that `bun run build` succeeds independently
- Check that `src-tauri/tauri.conf.json` `frontendDist` is `"../build"` (relative to `src-tauri/`)
- Check that all plugin crates resolve: `cd src-tauri && cargo check`
- Check that icon files exist in `src-tauri/icons/`

Note: macOS code signing warnings are expected in development. The unsigned app will still run locally.
</action>

<acceptance_criteria>
- `bun tauri build` exits with code 0 (success)
- `src-tauri/target/release/bundle/` directory exists
- On macOS: a `.dmg` or `.app` file exists in the bundle directory
- No Rust compilation errors
- No Tauri bundling errors
</acceptance_criteria>

## Task 01-04-04: Verify DevTools are disabled in production build

<read_first>
- persona/src-tauri/tauri.conf.json (verify `"devtools": false`)
</read_first>

<action>
With the production binary running:

1. Right-click anywhere in the app → verify there is NO "Inspect" or "Inspect Element" option in the context menu
2. Try keyboard shortcuts that typically open DevTools:
   - **F12** → should not open DevTools
   - **Ctrl+Shift+I** (or **Cmd+Option+I** on macOS) → should not open DevTools
3. Verify no DevTools window appears

Note: The `devtools: false` setting in `tauri.conf.json` only affects production builds. In dev mode (`tauri dev`), DevTools are always accessible regardless of this setting.

If DevTools still open:
- Verify the `devtools` field is `false` in `tauri.conf.json` windows config
- This may require the `devtools` Cargo feature to NOT be enabled (it's not in our Cargo.toml, so should be fine)
- Some older Tauri v2 versions had a bug where `devtools: false` was ignored — ensure Tauri v2 is at least 2.0.0
</action>

<acceptance_criteria>
- Right-click context menu in production build does NOT contain "Inspect" option
- F12 does NOT open DevTools in production build
- Ctrl+Shift+I / Cmd+Option+I does NOT open DevTools in production build
- No DevTools window appears in production
</acceptance_criteria>

## Task 01-04-05: Verify production CSP doesn't break app functionality

<read_first>
- persona/src-tauri/tauri.conf.json (review production CSP config)
</read_first>

<action>
With the production binary running, perform a thorough functional test:

1. **Route navigation**: Click all nav tabs (Chat, Library, Settings) — all should switch views
2. **Conversation interaction**: Click a conversation in the sidebar — messages should render
3. **Input interaction**: Type in the message input — text should appear
4. **Send message**: Press Enter — mock response should stream (Phase 1 behavior)
5. **Avatar images**: Character avatars should render (uses `data:` URIs for mock data)
6. **Font rendering**: Geist, Fraunces, and Geist Mono fonts should load
7. **Tailwind styles**: All styling should render correctly (background colors, borders, etc.)

Key CSP directives in production:
- `default-src 'self'` — only loads from bundled assets
- `style-src 'unsafe-inline' 'self'` — needed for Tailwind v4 inline styles + Svelte scoped styles
- `img-src 'self' asset: http://asset.localhost blob: data:` — needed for Tauri asset protocol and data URIs
- `connect-src ipc: http://ipc.localhost` — needed for Tauri IPC bridge
- `font-src 'self'` — loads bundled fonts

If styling is broken:
- Check that `style-src 'unsafe-inline'` is present (Tailwind v4 requires it)
- Check that font files are included in the build output

If images don't load:
- Check that `img-src` includes `data:` for mock avatar URIs
- Check that `img-src` includes `asset: http://asset.localhost` for Tauri asset protocol
</action>

<acceptance_criteria>
- All Tailwind styles render correctly in production (colors, spacing, borders)
- All fonts load (Geist body text, Fraunces display text, Geist Mono code)
- Character avatars render (data: URIs work)
- SvelteKit client-side routing works without CSP violations
- Tauri IPC bridge works (`connect-src ipc: http://ipc.localhost`)
- No visual regressions compared to dev mode
</acceptance_criteria>
