- Create mpsc channel
- std::thread::spawn that:
  a. Creates parent directory via `std::fs::create_dir_all`
  b. Opens Connection at db_path
  c. Runs migrations
  d. Seeds builtin presets
  e. Loops on `receiver.recv()` matching DbCommand variants
  f. Each match arm calls the appropriate CRUD function (from stub modules for now) and sends result via oneshot
- Returns `Ok(DbWorker { sender })`

**DbWorker::send(&amp;self, cmd: DbCommand) -&gt; Result&lt;(), String&gt;:**

- Sends command through mpsc::Sender, maps error to String

**unsafe impl Send for DbWorker {}**
**unsafe impl Sync for DbWorker {}**
(SAFETY: DbWorker only contains mpsc::Sender which is Send + Sync. Connection stays on worker thread.)

For CRUD module stubs referenced in match arms, use `todo!("implement in plan 02-02")` in the stub functions so the code compiles but will panic if called prematurely.

## Trust Boundaries

| Boundary               | Description                                                                                              |
| ---------------------- | -------------------------------------------------------------------------------------------------------- |
| Filesystem to DB       | Database file is created in platform data directory; corrupted files could cause migration failure       |
| Tauri IPC to DB Worker | Commands from frontend travel through Tauri IPC to DB worker; malicious frontend could send crafted data |

## STRIDE Threat Register

| Threat ID | Category | Component   | Disposition | Mitigation                                                                                                                |
| --------- | -------- | ----------- | ----------- | ------------------------------------------------------------------------------------------------------------------------- |
| T-02-01   | S        | DB Worker   | mitigate    | UUID v4 generation prevents ID prediction; no user-supplied IDs accepted                                                  |
| T-02-02   | I        | FTS5 search | mitigate    | FTS5 query sanitization via sanitize_fts_query() wraps in double quotes after escaping — prevents FTS5 operator injection |
| T-02-03   | D        | DB file     | accept      | Database file stored in user data directory; OS-level file permissions are the protection boundary                        |

</threat_model>
