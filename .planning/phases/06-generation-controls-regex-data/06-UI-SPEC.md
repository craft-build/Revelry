# Phase 6 — UI Design Contract

> Visual and interaction contract for Generation Controls, Regex & Data. Generated by gsd-ui-researcher.
> GTK4/libadwaita + Relm4 native desktop application. Design system inherited from Phase 1, extended by Phases 3, 4, and 5.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Adwaita (libadwaita v1.5+) |
| Preset | Adwaita default (system-managed light/dark) |
| Component library | GTK4 + libadwaita widgets |
| Icon library | relm4-icons 0.11.0 (bundled Adwaita symbolic icons) |
| Font | System font (Adwaita Sans / Inter variant on GNOME; system-ui on macOS/Windows) |
| CSS framework | GTK CSS via libadwaita stylesheet |

**Inheritance:** Spacing, typography, and color contracts are fully inherited from Phase 1 UI-SPEC (§Spacing Scale, §Typography, §Color). This document lists Phase 6 additions and exceptions only. Do not redefine base tokens.

---

## Spacing Scale

Inherited from Phase 1 (multiples of 4):

| Token | GTK Value | Usage |
|-------|-----------|-------|
| xs | 4 | Icon gaps, inline padding |
| sm | 8 | Compact element spacing |
| md | 12 | Default element spacing (Adwaita standard) |
| lg | 16 | Section padding, content margins within AdwClamp |
| xl | 24 | Section breaks, AdwPreferencesGroup spacing |
| 2xl | 32 | Page-level padding, sidebar/content margins |
| 3xl | 48 | Major section breaks, welcome/empty state spacing |

**Phase 6 Additions & Exceptions:**
- **Regex script row minimum height:** 48px — compact rows for script list, matching AdwActionRow density (same as lorebook entry rows in Phase 5)
- **Regex script list row spacing:** 4px (xs) between rows — compact list feel
- **Preset parameter row spacing:** 12px (md) between parameter rows within the editor group — standard Adwaita preferences density
- **Regex test panel border spacing:** 8px (sm) — gap between the test input area and before/after display
- **Before/after display area minimum height:** 80px — enough to show 3-4 lines of sample output
- **Backup/restore button group spacing:** 12px (md) between export/import buttons
- **Stop sequences tag list spacing:** 4px (xs) between tag chips — tight packing for tag-style stop sequences

## Typography

Inherited from Phase 1 — use Adwaita CSS style classes exclusively. No hard-coded sizes or weights.

| Role | Adwaita CSS Class | Approx. Size | Weight | Line Height | Phase 6 Usage |
|------|-------------------|-------------|--------|-------------|---------------|
| Body | `.body` | 14pt | 400 | 1.5 | Parameter descriptions, preset details, regex test output |
| Heading | `.heading` | 16pt | 700 | 1.2 | Preset editor section titles, regex editor section titles |
| Caption | `.caption` | 12pt | 400 | 1.4 | Parameter value hints, built-in preset badge, script flags preview, token counts |
| Caption Heading | `.caption-heading` | 12pt | 700 | 1.4 | Script name in list rows, preset name in list rows |
| Title 4 | `.title-4` | 18pt | 700 | 1.2 | Preset editor title, regex editor title, backup page title |
| Dimmed | `.dimmed` / `.caption, .dimmed` | 12pt | 400 | 1.4 | Disabled script names, "Built-in" badge for starter presets, parameter range hints |

**Phase 6 Specific:**
- **Preset name in list:** `.caption-heading` class — compact but bold for scanability (same as lorebook entry names)
- **Parameter values in preset list:** `.caption` class — e.g., "Temp: 1.2 · Top-P: 0.9"
- **Built-in preset indicator:** `.caption` + `.accent` class — "Built-in" label next to Creative/Balanced/Precise
- **Script name in list:** `.caption-heading` class
- **Script flags preview in list:** `.caption` class — e.g., "gi · Find: .*? · Replace: $1"
- **ReDoS warning:** `.error` class on GtkLabel — bold red warning when pattern fails validation
- **Regex test before/after labels:** `.caption-heading` class — "Before" and "After" labels
- **Regex test output (before):** `.body` class in GtkTextView (read-only)
- **Regex test output (after):** `.body` class in GtkTextView (read-only), with `.accent` on the GtkFrame border when changes are detected

## Color

Inherited from Phase 1 — use Adwaita semantic CSS variables exclusively.

| Role | CSS Variable | Light Approx. | Dark Approx. | Phase 6 Usage |
|------|-------------|---------------|--------------|---------------|
| Dominant | `--window-bg-color` | #ffffff | #1c1c1c | Inherited — no change |
| Secondary | `--card-bg-color` | #f6f5f4 | #2d2d2d | Regex test panel background, preset parameter editor background |
| Accent | `--accent-bg-color` | #3584e4 | #3584e4 | See extended reserved list below |
| Destructive | `--destructive-bg-color` | #e01b24 | #e01b24 | Delete preset/script confirmation, import data confirmation |
| Success | `--success-bg-color` | #33d17a | #33d17a | Regex validation passed indicator, export success toast |
| Warning | `--warning-bg-color` | #f6d32d | #e5a50a | ReDoS vulnerability warning badge |
| Error | `--error-bg-color` | #e01b24 | #e01b24 | ReDoS validation failure, regex syntax error, import version mismatch |

**Accent reserved-for (Phase 6 extensions):**
- `suggested-action` buttons: "Create Preset", "Save Preset", "Add Script", "Save Script", "Export Data"
- Active/selected preset in chat header popover (checkmark + row highlight)
- Currently assigned preset indicator in Settings and Character Editor dropdowns
- "Built-in" accent label on starter presets (Creative, Balanced, Precise)
- Regex test panel "After" frame border when transformations are applied
- **Not for:** Regex test input/output text, parameter value labels

**Phase 6 Style Class Usage:**
- `.suggested-action` → primary actions (Create Preset, Save Preset, Add Script, Save Script, Export Data)
- `.destructive-action` → delete preset/script buttons, import data confirmation button
- `.error` → ReDoS validation failure message, regex syntax errors, import version mismatch
- `.warning` → ReDoS vulnerability warning on borderline patterns (when pattern compiles but is flagged)
- `.caption` + `.dimmed` → built-in preset read-only indicator, disabled script state, parameter hints
- `.accent` → "Built-in" label, active preset checkmark, regex test panel highlight when changes detected

## Visual Hierarchy & Focal Points

### Settings — Presets Page
**Focal point:** Preset list rows — the primary content. Preset names in `.caption-heading` draw attention first, followed by parameter summary and built-in indicator.

**Secondary hierarchy:**
1. "Create Preset" button — primary action for empty state
2. Default preset dropdown — controls global assignment
3. Built-in preset lock icons — read-only indicators

### Character Editor — Regex Scripts Page
**Focal point:** Regex script list rows — the primary content area. Script names in `.caption-heading` draw attention first, followed by flags preview and enabled/disabled state.

**Secondary hierarchy:**
1. "Add Script" button — primary action for empty state
2. Per-character preset dropdown — assignment control (on Identity page, not Regex page)
3. Script count indicator

### Regex Script Editor — Test Panel
**Focal point:** "After" display area — the transformed output is what the user cares about. The `.accent` border highlight on the "After" frame when changes are detected draws the eye.

**Secondary hierarchy:**
1. "Before" display area — reference comparison
2. Test input area — where sample text goes
3. ReDoS validation warning (if present) — critical safety indicator

### Settings — Data Page
**Focal point:** Export buttons — primary positive actions (non-destructive, creating new files). These are the user's first interaction with backup/restore.

**Secondary hierarchy:**
1. Import button — destructive action, requires confirmation
2. File path display (after export) — confirmation of success

## Layout Specifications

### 1. Settings — Presets Page

A new `AdwPreferencesGroup` added to the Settings panel within the existing `AdwClamp`. The group contains the default preset dropdown and a list of all presets (built-in + custom).

```
AdwPreferencesGroup "Generation Presets":
├── AdwPreferencesRow "Default Preset"
│   └── gtk::DropDown (None + preset names)
│       subtitle: "Used when a character has no preset assigned"
│
├── GtkLabel (.caption, .dimmed): "Presets control how the AI generates responses. Assign a preset at the character or conversation level to override this default."
│
├── GtkScrolledWindow (vexpand, min-content-height: 200)
│   └── GtkListBox (.boxed-list)
│       └── [Preset rows, or empty state]
│
└── GtkButton "Create Preset" (.flat, halign: start)
    connect_clicked => CreatePreset
```

### 2. Preset Row in List

Each preset appears as an `AdwActionRow` in the `.boxed-list`. Built-in presets show a lock icon and "Built-in" badge; custom presets show edit/delete actions.

```
AdwActionRow (preset row):
├── title: {preset.name}                          (.caption-heading)
├── subtitle: "Temp: {n} · Top-P: {n} · Max: {n}" (.caption, max 1 line, ellipsize)
├── prefix: GtkImage "lock" (only for built-in)    (.dimmed, 16px)
├── suffix: GtkLabel "Built-in" (only for built-in) (.caption, .accent)
├── suffix: GtkButton "Duplicate" (built-in only)  (.flat)
├── suffix: GtkButton "Edit" (custom only)          (.flat)
└── suffix: GtkButton "Delete" (custom only)         (.flat, .destructive-action on hover)
```

**Preset row states:**

| State | Visual | Interaction |
|-------|--------|-------------|
| Built-in | Lock icon prefix, "Built-in" `.accent` badge, Duplicate button only | No edit/delete |
| Custom | No lock, Edit + Delete buttons | Edit, Delete clickable |
| Custom, assigned | No additional visual change in list | Edit, Delete clickable (assignment persists until explicitly changed) |

### 3. Preset Editor (AdwPreferencesWindow sub-dialog)

When the user clicks "Create Preset" or "Edit" on a custom preset, a modal `AdwPreferencesWindow` opens. For built-in presets, only "Duplicate" is available (which opens the editor pre-filled with the built-in's values and a new name).

```
AdwPreferencesWindow "New Preset" / "Edit Preset":
├── AdwHeaderBar
│   └── title: "New Preset" or "Edit Preset"
│
├── AdwPreferencesPage
│   ├── AdwPreferencesGroup "Preset Details"
│   │   └── AdwEntryRow "Name"
│   │       subtitle: "A short name to identify this preset"
│   │
│   ├── AdwPreferencesGroup "Sampling Parameters"
│   │   ├── AdwSpinRow "Temperature"
│   │   │   subtitle: "Controls randomness. Higher = more creative, lower = more focused."
│   │   │   range: 0.0–2.0, step: 0.1, default: 0.8
│   │   ├── AdwSpinRow "Top-P"
│   │   │   subtitle: "Nucleus sampling threshold. Lower = more focused vocabulary."
│   │   │   range: 0.0–1.0, step: 0.05, default: 0.9
│   │   ├── AdwSpinRow "Max Tokens"
│   │   │   subtitle: "Maximum tokens in the AI response. 0 = no limit."
│   │   │   range: 0–128000, step: 1, default: 0
│   │   ├── AdwSpinRow "Frequency Penalty"
│   │   │   subtitle: "Reduces repetition of frequent tokens. 0 = no penalty."
│   │   │   range: 0.0–2.0, step: 0.1, default: 0.0
│   │   ├── AdwSpinRow "Presence Penalty"
│   │   │   subtitle: "Encourages new topics. 0 = no penalty."
│   │   │   range: 0.0–2.0, step: 0.1, default: 0.0
│   │   └── GtkLabel (.caption, .dimmed): "Not all providers support all parameters. Unsupported parameters are silently skipped."
│   │
│   ├── AdwPreferencesGroup "Stop Sequences"
│   │   ├── AdwEntryRow "Stop Sequences"
│   │   │   subtitle: "Comma-separated. AI stops generating when it encounters any of these."
│   │   │   placeholder: "e.g. \\n, END, ---"
│   │   └── GtkLabel (.caption, .dimmed): "Leave empty for no stop sequences. Most providers support up to 4 sequences."
│   │
│   └── AdwPreferencesGroup
│       └── GtkBox (horizontal, spacing: 12, halign: end)
│           ├── GtkButton "Cancel" (.flat)
│           └── GtkButton "Save Preset" (.suggested-action)
```

**Validation:**
- Name must be non-empty — show `.error` on the AdwEntryRow if empty on save attempt
- Name must not duplicate a built-in preset name — show `.error` if conflicts with Creative/Balanced/Precise
- All numeric parameters are always valid within AdwSpinRow ranges — no validation errors possible
- Stop sequences: free-form text, no validation (comma-separated, empty is valid)

**Close Action:**
- Close/Cancel at any point: `AdwAlertDialog` confirmation if any field has unsaved changes
  - "Discard changes?" → [Keep Editing] [Discard]

```
│   │   └── GtkLabel (.caption, .dimmed): "Changes are highlighted when the output differs from the input."
│   │
│   └── AdwPreferencesGroup
│       └── GtkBox (horizontal, spacing: 12, halign: end)
│           ├── GtkButton "Cancel" (.flat)
│           └── GtkButton "Save Script" (.suggested-action)
```

**Validation (D-06):**
- Name must be non-empty — show `.error` on the AdwEntryRow if empty on save attempt
- Find pattern must be non-empty — show `.error` if empty on save attempt
- Find pattern must pass ReDoS validation — `regex::RegexBuilder::size_limit()` check
  - **On validation failure:** Show `redos_warning` GtkLabel with `.error` class: "This pattern may cause catastrophic backtracking (ReDoS). Please simplify the regex or add more specific constraints."
  - **On validation failure:** Block saving. User must fix the pattern before the script can be saved.
  - **On validation failure:** Disable the "Enabled" switch (force to disabled) — cannot enable a dangerous pattern
- Replace pattern is optional (empty replace = deletion of matches)
- Flags must be valid characters (i, m, s, g only) — show `.error` if invalid flag character detected

**Close Action:**
- Close/Cancel at any point: `AdwAlertDialog` confirmation if any field has unsaved changes
  - "Discard changes?" → [Keep Editing] [Discard]

**ReDoS Validation Behavior (D-06):**
1. User types in Find Pattern field
2. On every change, compile the regex with `regex::RegexBuilder::size_limit(1_000_000)` (1MB backtracking limit)
3. **If compilation succeeds:** Hide redos_warning, enable Save button
4. **If compilation fails (timeout/size exceeded):** Show redos_warning, disable Save button, force Enabled switch off
5. **If compilation fails (syntax error):** Show `.error` message with the regex crate's error message (e.g., "unclosed group"), disable Save button

**Test Panel Behavior (D-07):**
1. User types in the test input GtkTextView
2. On every change, run the current find/replace/flags against the test input
3. Display the unmodified input in the "Before" read-only view
4. Display the transformed output in the "After" read-only view
5. If the output differs from the input, add `.accent` CSS class to the "After" frame border
6. If the pattern is invalid (ReDoS or syntax error), show the error in the "After" area instead of output
7. Test panel updates in real-time as the user types — no "Run Test" button needed

5. User clicks "Save Preset" (`.suggested-action`)
6. Validation: name required, name must not duplicate built-in

8. **On invalid:** show `.error` label below the failing field; do not close editor

6. User clicks "Save Preset"

### Preset Assignment Resolution (D-03)

```
User starts conversation → System evaluates hierarchy:
  1. conversation.generation_preset_id set? → Use that preset
  2. Else: character.default_preset_id set? → Use that preset
  3. Else: app_settings.default_preset_id set? → Use global default
  4. Else: No preset → Send no parameter overrides (provider defaults)
```

**Visual feedback for active source:**
- Chat header always shows the *resolved* preset name, never the source
- Settings dropdown shows "(None)" when no global default
- Character editor shows "(None)" when no character default
- Chat popover shows checkmark on resolved preset; "(Default)" option clears conversation override

1. User clicks preset button in chat header (e.g., "🎯 Balanced")
2. `GtkPopover` opens with list of all presets + "(Default)" option
3. User selects a preset → popover closes
4. Update `conversation.generation_preset_id` in database
5. Toast: "Preset changed to {Name}" or "Preset changed to Default"
6. Future messages use new preset's generation parameters
7. In-progress stream is NOT affected — changes apply to next message only

### Regex Script Add Flow

1. User clicks "Add Script" button on Regex Scripts page in Character Editor
2. `AdwPreferencesWindow` opens with title "New Script"
3. All fields start at defaults: empty name, empty find pattern, empty replace pattern, flags="gi", execution order = next available (max existing + 1), enabled=true
4. User fills in fields
5. ReDoS validation runs in real-time as the user types the find pattern
6. Test panel updates in real-time as the user types in test input or changes find/replace/flags
7. User clicks "Save Script" (`.suggested-action`)
8. Validation: name required, find pattern required, find pattern must pass ReDoS check
9. **On valid:** dispatch `SaveRegexScript(script)` → DbService; close editor; toast "Script added"
10. **On invalid:** show `.error` label; do not close editor

### Regex Script Edit Flow

1. User clicks "Edit" on a script row
2. `AdwPreferencesWindow` opens with title "Edit Script", fields pre-populated from script data
3. User modifies fields
4. ReDoS validation and test panel behave same as add flow
5. User clicks "Save Script"
6. Validation same as add flow
7. **On valid:** dispatch `SaveRegexScript(script)` → DbService; close editor; toast "Script updated"
8. **On cancel with changes:** `AdwAlertDialog` "Discard changes?" → [Keep Editing] [Discard]

### Regex Script Delete Flow

1. User clicks "Delete" on a script row (hover reveals `.destructive-action` style)
2. `AdwAlertDialog` appears:
   - Title: "Delete Script?"
   - Body: "This will permanently delete '{name}' and remove its post-processing from AI responses. This cannot be undone."
   - Buttons: [Don't Delete] [Delete] (`.destructive-action`)
3. **On confirm:** dispatch `DeleteRegexScript(id, character_id)` → DbService
4. On `RegexScriptDeleted`: remove row from list, toast "Script deleted"

### Regex Script Enable/Disable Toggle

1. User toggles the "Enabled" AdwSwitchRow in the script editor
2. Script's `enabled` field is updated
3. Script row's visual state updates (`.dimmed` when disabled)
4. Script is saved to database immediately (no confirmation needed for toggle)

## Phase 6 Specific Notes

### Preset Assignment — Exact Persona Hierarchy Clone

Per D-03, the preset assignment hierarchy is an exact structural clone of the persona assignment hierarchy from Phase 4. The three levels are:
1. **Global default** — in Settings (AdwPreferencesRow with DropDown)
2. **Per-character default** — in Character Editor Identity page (AdwPreferencesRow with DropDown)
3. **Per-conversation override** — in Chat Header (MenuButton + Popover)

The resolution logic is identical: conversation → character → global → none. The UI components are identical: DropDown in Settings and Character Editor, MenuButton + Popover in Chat Header. The only differences are the data source (presets instead of personas) and the fallback behavior (no parameter overrides vs. raw "User" name).

### Preset Editor — Simpler Than Persona Wizard

The preset editor is a single-page `AdwPreferencesWindow` (not a multi-step wizard like the Persona Editor). All parameters fit on one page with three logical groups: Preset Details, Sampling Parameters, Stop Sequences. No step navigation is needed because the form is short enough to scroll in a single page.

### Regex Script Editor — Lorebook Editor Pattern

The regex script editor follows the same pattern as the LorebookEditor (Phase 5):
- List panel with `.boxed-list` rows in the Character Editor page
- Sub-dialog `AdwPreferencesWindow` for editing individual scripts
- Add/Edit/Delete/Enable-Disable flows
- Sequential ordered items with sort_order

The key additions beyond the LorebookEditor pattern are:
1. **Inline test panel** — the "Test Script" group at the bottom of the editor dialog
2. **ReDoS validation** — real-time pattern validation that blocks saving
3. **Before/after display** — dual read-only GtkTextView panels for visual comparison

### ReDoS Validation — Design-Time Enforcement Only

Per D-06, ReDoS validation happens at design-time (when the user writes the pattern), not at runtime (when the pattern is applied to AI responses). The validation uses `regex::RegexBuilder::size_limit()` to cap backtracking at 1MB. If a pattern fails this check, the user must fix it before saving. This ensures that no dangerous pattern ever reaches the runtime pipeline.

### Stop Sequences — Comma-Separated Entry (Not Tag-Style List)

Per the agent's discretion area in CONTEXT.md, stop sequences use a simple comma-separated `AdwEntryRow` rather than a tag-style chip list. This is simpler to implement and matches how most AI APIs accept stop sequences (as a simple list). The comma-separated format is familiar from the Keywords field in the Lorebook Editor. Tag-style lists are deferred as a future polish item.

### Built-In Presets — Read-Only with Duplicate

Per D-14, the three built-in presets (Creative, Balanced, Precise) are always present and cannot be edited or deleted. They appear in every preset dropdown. Custom presets appear below them in lists and dropdowns. The "Duplicate" button on built-in presets opens the preset editor pre-filled with the built-in's values and the name "{Original} Copy".

### Import Destructive Confirmation — No Merge Mode

Per D-10, import replaces all existing data. There is no merge or side-by-side import mode. This matches SillyTavern's behavior and keeps the implementation simple. The destructive confirmation dialog makes this clear with a warning message and `.destructive-action` styling on the confirm button.

### Backup Timestamps in File Names

Export file names include timestamps in `YYYY-MM-DD_HHMMSS` format (e.g., `revelry_backup_2026-05-08_143022.sql`). This makes backup files self-documenting and prevents accidental overwrites when exporting multiple backups.

### Preset Button Emoji

The preset button in the chat header uses the 🎯 emoji as a visual differentiator from the persona button ("as {Name}"). This is a rare acceptable use of emoji in the UI because it serves as a visual icon in a space-constrained header bar where a separate icon widget would add too much complexity. The emoji is used as a prefix, not as the sole content.

### Regex Scripts — Character-Level Only

Regex scripts are per-character (stored in the `regex_scripts` table with a `character_id` FK). There are no global or per-conversation regex scripts. This is simpler than the preset/persona assignment hierarchy and matches the SillyTavern pattern where regex scripts are character-level extensions.

### No Preset Sharing/Export (Deferred)

Per the 06-CONTEXT.md deferred items, preset sharing/export between users and regex script import/export as standalone files are deferred. Presets and scripts are managed within the app only, included in the full data backup/restore.
