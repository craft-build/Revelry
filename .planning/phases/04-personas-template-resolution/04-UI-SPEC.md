# Phase 4 — UI Design Contract

> Visual and interaction contract for Personas & Template Resolution. Generated by gsd-ui-researcher.
> GTK4/libadwaita + Relm4 native desktop application. Design system inherited from Phase 1 and extended with Phase 3 chat patterns.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Adwaita (libadwaita v1.5+) |
| Preset | Adwaita default (system-managed light/dark) |
| Component library | GTK4 + libadwaita widgets (AdwPreferencesWindow, AdwNavigationView, AdwComboRow, AdwEntryRow, AdwActionRow, AdwMessageDialog, AdwStatusPage, AdwToast, AdwAvatar, AdwClamp, AdwToolbarView) |
| Icon library | relm4-icons 0.11.0 (bundled Adwaita symbolic icons) |
| Font | System font (Adwaita Sans / Inter variant on GNOME; system-ui on macOS/Windows) |
| CSS framework | GTK CSS via libadwaita stylesheet |

**Inheritance:** Spacing, typography, and color contracts are fully inherited from Phase 1 UI-SPEC. This document lists Phase 4 additions and exceptions only. Do not redefine base tokens.

## Spacing Scale

Inherited from Phase 1 (multiples of 4):

| Token | GTK Value | Usage |
|-------|-----------|-------|
| xs | 4 | Icon gaps, inline padding |
| sm | 8 | Compact element spacing |
| md | 12 | Default element spacing (Adwaita standard) |
| lg | 16 | Section padding, content margins within AdwClamp |
| xl | 24 | Section breaks, AdwPreferencesGroup spacing |
| 2xl | 32 | Page-level padding, sidebar/content margins |
| 3xl | 48 | Major section breaks, welcome/empty state spacing |

**Phase 4 Additions & Exceptions:**
- **Persona library row height:** 64px minimum (icon 48px + lg padding top/bottom) — taller than standard AdwActionRow for richer preview
- **Wizard step content padding:** 24px (xl) horizontal within AdwClamp; vertical spacing between field groups is xl (24px)
- **Persona block preview area:** 16px (lg) internal padding, `--card-bg-color` background
- **Persona popover row padding:** 12px (md) vertical, 16px (lg) horizontal
- **Read-only text view margins:** 8px (sm) internal padding for block preview

## Interaction Specifications

### Persona Editor Wizard Flow

1. User clicks "Create Persona" in library tab or "Edit" on a persona row.
2. **If New:** PersonaEditor opens with empty fields, step 1 active.
   **If Edit:** PersonaEditor opens with populated fields, step 1 active.
3. User fills step fields and clicks **Next**. Validation runs:
   - If invalid: `.error` label appears below invalid field; button remains sensitive.
   - If valid: advances to next step.
4. User can click **Back** on steps 2-5 to return and edit.
5. On Review step, user clicks **Save**.
   - Dispatches `SavePersona` to DbService.
   - On `PersonaSaved`: closes editor, toast "Persona created" / "Persona updated", library refreshes.
   - On error: shows `.error` toast, keeps editor open.
6. **Cancel** at any step closes editor with `AdwMessageDialog` confirmation if any field has unsaved changes:
   - "Discard changes?" → [Keep Editing] [Discard]

### Persona Assignment Hierarchy Resolution (UI Behavior)

```
User starts conversation → System evaluates hierarchy:
  1. conversation.creator_persona_id set? → Use that persona
  2. Else: character.default_persona_id set? → Use that persona
  3. Else: app_settings.default_persona_id set? → Use global default
  4. Else: No persona → {{user}} resolves to "User"
```

**Visual feedback for active source:**
- Chat header always shows the *resolved* persona name, never the source.
- Settings dropdown shows `(None)` when no global default.
- Character editor shows `(None)` when no character default.
- Chat popover shows checkmark on resolved persona; `(Default)` option clears conversation override.

### Persona Delete Flow

1. User clicks "Delete" on persona row (hover reveals `.destructive-action` style).
2. `AdwMessageDialog` appears:
   - Title: "Delete Persona?"
   - Body: "This will permanently delete '{name}'. Conversations using this persona will fall back to the next available persona in the assignment hierarchy."
   - Buttons: [Cancel] [Delete] (`.destructive-action`)
3. On confirm: dispatch `DeletePersona(id)` → DbService.
4. On `PersonaDeleted`: remove row from library, toast "Persona deleted".
5. Conversations referencing deleted persona automatically resolve to next hierarchy level on next prompt assembly (no UI notification needed).

### Chat Header Persona Change

1. User clicks persona subtitle in chat header (e.g., "as Alice").
2. `GtkPopover` opens with list of all personas + `(Default)` option.
3. User selects a persona → popover closes.
4. Update `conversation.creator_persona_id` in database.
5. Toast: "Persona changed to {Name}".
6. Future messages use new persona data in prompt assembly.
7. Existing messages in conversation are **not** retroactively modified.

## Phase 4 Specific Notes

### Template Variables — No Dedicated Preview UI

Template resolution (`{{user}}`, `{{char}}`, `{{persona.*}}`) happens entirely at backend prompt-assembly time (D-07). There is **no dedicated template preview/debug pane** in Phase 4. The user experiences correct resolution through the AI's responses (addressing them by persona name and traits). The **only** preview of assembled persona data is the read-only block in the Review step of the Persona Editor.

### Persona Avatars Deferred

Persona rows use `user-symbolic` icon placeholder (48px). Custom avatar upload is deferred to v2 (PERS-A04 area). Do not implement AdwAvatar with image for personas in Phase 4.

### Character Editor Template Tip

Adding a `.caption, .dimmed` tip below the Description field in the Character Editor's Basic Info step (D-13 context). This is a minor Phase 4 addition to an existing Phase 2 UI. The tip informs users that template variables are now functional.

### Mid-Conversation Persona Switching

Per D-14, users can change persona mid-conversation via the chat header popover. This updates `conversation.creator_persona_id` immediately. Existing messages are preserved as-is; only future messages use the new persona. This is **not** the v2 retroactive branch regeneration (PERS-A01 deferred).
