<action>
1. Create `src/lib/components/lorebooks/LorebookEditor.svelte`:

This is a wider dialog (`max-w-3xl`) for editing a lorebook and its entries. Key design:
- Props: `open: boolean`, `onOpenChange: (open: boolean) => void`, `mode: 'create' | 'edit'`, `lorebook?: Lorebook`
- State:
  - `lorebookData: { name: string, description: string }`
  - `entries: LorebookEntry[]`
  - `selectedEntryId: string | null`
  - `isSaving: boolean`
  - `backendError: string | null`
  - `keywordsTestOpen: boolean`
  - `sampleText: string`
  - `testResults: KeywordTestResult[]`

Dialog title: `mode === 'create' ? 'New lorebook' : 'Edit {lorebook.name}'`

Layout (two-column within the dialog body):
- **Left column** (~40%): Entry list + "Add entry" button
  - Each entry shows: first keyword (truncated), content preview (truncated to ~60 chars), selected state highlighting
  - Click an entry to select it → right column shows its form
  - Trash icon on each entry for deletion (with inline confirmation or immediate delete)
  - "Add entry" button at the bottom of the list
- **Right column** (~60%): Selected entry form (or "Select an entry" placeholder)
  - Keys: `Input` with label "Keywords", placeholder "comma-separated keywords"
  - Secondary keys: `Input` with label "Secondary keys", placeholder "optional secondary keywords"
  - Content: `Textarea` with label "Content" (rows=4)
  - Position: `Select` with label "Position", options: "before_char" → "Before char", "after_char" → "After char", "at_depth" → "At depth"
  - Depth: `Input` type="number" with label "Depth", default 4
  - Activation state: `Select` with label "Activation", options: "always" → "Always", "character_only" → "Character only", "user_only" → "User only"
  - Save entry button (saves just this entry via `api.saveLorebookEntry`)

**Test Keywords panel** (bottom accordion):
- Collapsible section with header "Test Keywords" and a chevron icon
- When expanded:
  - `Textarea` for sample text with placeholder "Type sample conversation text here…"
  - "Run test" button that calls `testLorebookKeywords(entries, sampleText)` via the api
  - Results area: list of entries with their matched keys highlighted in accent color
    - For each result where `is_activated === true`:
      - Entry content preview (first 80 chars)
      - "Matched: key1, key2" with keys styled in accent
    - Entries with no matches shown as muted

Save lorebook logic:
- The "Create lorebook" / "Save changes" button saves the lorebook name and description via `app.createLorebook()` or `app.updateLorebook()`
- Entries are saved individually when the user clicks "Save entry" in the right column
- On creating a new lorebook: first save the lorebook, then create a default empty entry

Loading entries:
- On `mode === 'edit'` and `open === true`, call `getLorebookEntries(lorebook.id)` via api and populate the entries list
- Store entries in local component state (not in AppState — entries are only needed within the editor)

Validation:
- Lorebook name: non-empty → error "Name is required."
- Entry keys: at least one non-empty key → error "At least one keyword is required."
- Entry content: non-empty → error "Content is required."
</action>
