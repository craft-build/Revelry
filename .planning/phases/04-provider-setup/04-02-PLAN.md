## Trust Boundaries

| Boundary                                       | Description                                                               |
| ---------------------------------------------- | ------------------------------------------------------------------------- |
| User input → ProviderEditorDialog              | User-entered provider data (name, URL, model names, API key) is untrusted |
| ProviderEditorDialog → AppState.createProvider | Form data crosses into application state                                  |
| AppState → Tauri IPC                           | Application state sends provider data to Rust backend                     |

## STRIDE Threat Register

| Threat ID | Category               | Component                                | Disposition | Mitigation Plan                                                                                                                    |
| --------- | ---------------------- | ---------------------------------------- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| T-04-07   | Information Disclosure | API key in frontend state                | mitigate    | API key is only in form state during save; never stored in AppState.providers; has_api_key boolean is the only persisted indicator |
| T-04-08   | Tampering              | Invalid provider form input              | mitigate    | Client-side validation in ProviderEditorDialog: required fields, numeric ranges, at least one model                                |
| T-04-09   | Denial of Service      | Keyring unavailable during provider save | mitigate    | createProvider saves provider to DB even if keyring save fails; shows error banner for key failure; Ollama works without key       |

</threat_model>
