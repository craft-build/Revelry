<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frontend → Tauri IPC | Untrusted input (user-entered provider name, base_url, model names) crosses to Rust backend |
| Rust → OS Keychain | API key storage in platform keychain via keyring-core |
| Tauri IPC → Frontend | Backend responses MUST never contain API key values |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | has_api_key command | mitigate | Returns boolean only; load_key result checked but never serialized into response |
| T-04-02 | Information Disclosure | providers table | mitigate | No api_key column exists (migration adds only models and default_params TEXT columns) |
| T-04-03 | Information Disclosure | KeyringStore logging | mitigate | Never log API key values; only log operation success/failure |
| T-04-04 | Denial of Service | Keyring unavailable on Linux | mitigate | is_available() check returns false gracefully; keyring ops return errors that frontend handles (D-09) |
| T-04-05 | Tampering | Provider CRUD SQL | mitigate | All queries use rusqlite params![] macro for parameterized queries |
| T-04-06 | Information Disclosure | delete_provider keyring cleanup | accept | Best-effort deletion silently continues if key doesn't exist or keyring is unavailable after DB deletion succeeds |
</threat_model>
